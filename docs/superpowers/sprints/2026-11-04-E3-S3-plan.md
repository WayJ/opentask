# E3-S3 — Inbox 通知流（指派 / 评论 / @）

本文件即 sprint 台账。分支 `sprint/E3-S3`（基于 `sprint/E3-S2` tip `4475f90`）；worktree `/workspace/opentask-worktrees/E3-S3`。本轮不推远程。

## Decisions (D-x)

| id | decision | rationale | rejected alternatives |
|---|---|---|---|
| D1 | Inbox = 库内 `notifications` 表 + REST API；不做邮件/IM 外发 | Epic ADR D9 | 邮件投递 —— 明确排除 |
| D2 | 类型枚举：`assigned` / `commented` / `mentioned`；`resource_type=issue` | 覆盖本 sprint 三触发器；可扩展 | 泛化 event bus —— 超出 S3 |
| D3 | 在 `IssueService.update_issue`（assignee 变更）与 `add_comment` 内挂钩，不散落 router | 任务约束；timeline 同路径 | 仅 router 侧副作用 —— 易漏 PUT/assignee 快捷入口 |
| D4 | 指派：通知新 assignee，且 actor≠recipient；评论：通知 issue 的 assignee+reporter（排除作者）+ 解析 `@username`/`@userId` 且仅工作区成员 | 避免自通知与跨租户噪音 | 通知全工作区 —— 拒绝 |
| D5 | API：`GET /api/inbox`（unread/page）、`POST /api/inbox/{id}/read`、`POST /api/inbox/read-all`；作用域=当前用户 + 可选 `X-Workspace-Id` | 与 S1 租户头一致 | 嵌套 `/workspaces/{id}/inbox` —— 多余 |
| D6 | 前端：顶栏铃铛 + `/inbox` 页（Naive UI）；点击进 issue 详情 | DESIGN.md / soybean | 复活 mission-center —— 排除 |
| D7 | 测试库走 `DBModel.metadata.create_all`；另写 alembic 迁移供 PG 部署 | 延续 S1 模式 | 仅 raw SQL bypass —— 不必要 |

## Acceptance Scenarios (S1–Sn)

| id | scenario | how to verify | expected |
|---|---|---|---|
| S1 | 指派产生 assigned 通知 | PUT assignee 后目标用户 GET inbox | 有 type=assigned 且未读 |
| S2 | 评论通知 assignee/reporter | POST comment 后 | type=commented；作者无自通知 |
| S3 | @mention 通知工作区成员 | 评论含 `@username` | type=mentioned |
| S4 | 列表隔离 | 用户 A 看不到用户 B 的通知 | 空或不含 |
| S5 | 标记已读 | POST read / read-all | read_at 非空；unread 过滤生效 |
| S6 | 前端 Inbox 静态 | lint/build + 组件入库 | 0 errors；铃铛与页面存在 |
| S7 | 浏览器 E2E（可选） | 真实会话点铃铛 | 若阻塞则 blocked |
