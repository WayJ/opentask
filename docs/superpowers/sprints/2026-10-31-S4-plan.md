## Stories & Tasks

### Wave 1 — 契约 API 层

- [ ] `backend/opentask/api/tasks/` 新模块：`GET /tasks`（过滤 status/assignee、分页 limit/offset、`updated_since` 增量游标）、`POST /tasks`、`GET /tasks/{id}`、`PATCH /tasks/{id}`、`DELETE /tasks/{id}`（软删除 is_deleted）
- [ ] 字段映射层：通用任务模型（id/title/description/status/assignee/url/timestamps + 可扩展 metadata）↔ Issue 模型双向转换；assignee 字符串 ID + metadata.username；labels ↔ tags 双向
- [ ] 状态映射骨架：IssueStatus（open/in_progress/feedback/resolved/closed/rejected）↔ 通用任务状态的默认映射表（可配置化留待 S5，S4 用默认表）
- [ ] POST 创建回写：title/description/assignee/status/labels 完整落库（经 issue service）
- [ ] PATCH 状态变更写入既有 timeline 记录
- [ ] 单元测试：CRUD 全路径 + updated_since 游标边界（同游标重复拉取不重复、边界时刻含否语义）
- [ ] 路由注册进应用装配；导入图零缺失维持

## Definition of Done

- [ ] Orca 用「自定义任务源」注册 OpenTask 后，OpenTask 的 issue 能在 Orca 侧正常列出、读取、创建、更新、状态流转
- [ ] `GET /tasks` 支持 `updated_since` 增量游标，重复拉取同一游标不返回重复数据
- [ ] `POST /tasks` 创建的 issue 回传到 OpenTask 后，字段（title/description/assignee/status/labels）完整落库
- [ ] `PATCH /tasks/{id}` 更新状态后，OpenTask 内部 issue 状态同步变更，并写入既有 timeline 记录
- [ ] `DELETE /tasks/{id}` 采用软删除（OpenTask 现有 `is_deleted` 语义），不物理删除数据
- [ ] 状态映射可通过配置调整，未配置时使用默认映射表且能正确往返（Orca → OpenTask → Orca）
- [ ] 契约 OpenAPI spec 已生成并随代码发布，字段与实现一致
- [ ] 端点不可达、鉴权失败、schema 违规三类错误有独立的错误码与可读消息
- [ ] 该 API 层有单元测试覆盖 CRUD 全路径与增量游标边界
