# S7 — Jira 线格式兼容层：让 Orca 自建 Jira 集成直指 OpenTask

本文件即 sprint 台账。一个 sprint = 一个 worktree/分支（`sprint/E2-S7`，Orca 原生工作区，基于 main@f304a5b）。frontmatter worktree 为分支名。单 worker（生命周期闭环）。

## Decisions (D-x)

| id | decision | rationale | rejected alternatives |
|---|---|---|---|
| D1 | 先探测后实现：worker 首务是读本机 Orca 安装的 Jira 适配文档/技能（`orca skills get` 相关参考、`orca jira connection` 帮助、skill-guides）枚举其真实调用的 Jira REST 端点与字段，按实际需求面实现，不凭 Jira 官方 API 全集猜 | Orca 的 Jira 集成只用一个子集；实现它真实调用的部分才可验证 | 按官方 REST v2 全量模仿 —— 拒绝：工作量爆炸且不可验证 |
| D2 | 线格式层挂 `/rest/api/2/` 前缀，与 `/tasks` 契约层并列（D7 同构）；共用 mapping/auth/schemas 内核，不复制业务 | 单一事实源；Jira 层只是线格式适配 | 复制映射逻辑 —— 拒绝：漂移 |
| D3 | 鉴权对齐 Jira 惯例：Basic（user:token）与 Bearer PAT 均映射到 access_token 体系 | Orca 自建 Jira 配置面通常两者皆可配 | 新鉴权 —— 拒绝：D9 既定复用 |
| D4 | 验收以真实 Orca 注册为准：Orca 以自建 Jira 模式指向本机后端（uvicorn），五操作走通留证 | 这是 epic DoD 1 的完整形态；S6 的降级证据由本 sprint 升级取代 | 仅测试模拟 —— 拒绝：又回到不可验证 |

## Stories & Tasks

### Wave 1 — 探测与实现

- [ ] 探测：读本机 Orca 的 Jira 集成真实调用面（端点、字段、分页、鉴权头、transitions 用法）
- [ ] 实现 `/rest/api/2/` 兼容子集（预计：myself、search(JQL 子集→过滤器翻译)、issue get/create/update、transitions、project/field 元数据按需）
- [ ] Jira 字段投影：key(如 OPENTASK-1)/summary/description/status/assignee/priority/issuetype/updated ↔ 契约映射内核
- [ ] Basic/Bearer 鉴权映射 access_token
- [ ] 契约测试：Jira 线格式往返
- [ ] E2E：Orca 自建 Jira 注册 + 五操作留证（升级 S6 降级证据）

## Definition of Done

- [ ] Orca 用「自定义任务源」注册 OpenTask 后，OpenTask 的 issue 能在 Orca 侧正常列出、读取、创建、更新、状态流转
- [ ] `GET /tasks` 支持 `updated_since` 增量游标，重复拉取同一游标不返回重复数据
- [ ] `POST /tasks` 创建的 issue 回传到 OpenTask 后，字段（title/description/assignee/status/labels）完整落库
- [ ] `PATCH /tasks/{id}` 更新状态后，OpenTask 内部 issue 状态同步变更，并写入既有 timeline 记录
- [ ] `DELETE /tasks/{id}` 采用软删除（OpenTask 现有 `is_deleted` 语义），不物理删除数据
- [ ] 状态映射可通过配置调整，未配置时使用默认映射表且能正确往返（Orca → OpenTask → Orca）
- [ ] 契约 OpenAPI spec 已生成并随代码发布，字段与实现一致
- [ ] 端点不可达、鉴权失败、schema 违规三类错误有独立的错误码与可读消息
- [ ] 该 API 层有单元测试覆盖 CRUD 全路径与增量游标边界
