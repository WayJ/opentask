## Stories & Tasks

### Wave 1 — spec 与错误语义

- [ ] 契约路由 OpenAPI spec 导出（/tasks、/tasks/{id}、/tasks/token、/capabilities），随代码提交（backend/openapi_contract.json 或等价物）
- [ ] 错误语义定稿：401（CONTRACT_AUTH_MISSING/INVALID，S5 已有）/403（CONTRACT_FORBIDDEN）/503（CONTRACT_UNAVAILABLE）三类独立错误码字段 + 可读消息；契约层统一错误响应模型
- [ ] 契约测试补错误路径：无凭证/错凭证/禁操作/服务不可达四类用例
- [ ] spec 字段与实现一致性核对（导出 spec 与路由 schema 对账）

### Wave 2 — Orca 侧联调

- [ ] 探测本机 Orca 任务源注册能力（自定义任务源配置面）；可得则注册 http://localhost:8000 契约端点跑列出/读取/创建/更新/状态流转并留证
- [ ] 不可得则：记录 blocked 项 + 替代证据（契约套件 + capabilities 协商输出）， epic 关闭时列遗留

## Definition of Done

- [ ] Orca 用「自定义任务源」注册 OpenTask 后，OpenTask 的 issue 能在 Orca 侧正常列出、读取、创建、更新、状态流转
- [ ] `GET /tasks` 支持 `updated_since` 增量游标，重复拉取同一游标不返回重复数据
- [ ] `POST /tasks` 创建的 issue 回传到 OpenTask 后，字段（title/description/assignee/status/labels）完整落库
- [ ] `PATCH /tasks/{id}` 更新状态后，OpenTask 内部 issue 状态同步变更，并写入既有 timeline 记录
- [ ] `DELETE /tasks/{id}` 采用软删除（OpenTask 现有 `is_deleted` 语义），不物理删除数据
- [ ] 状态映射可通过配置调整，未配置时使用默认映射表且能正确往返（Orca → OpenTask → Orca）
- [ ] 契约 OpenAPI spec 已生成并随代码发布，字段与实现一致
- [ ] 端点不可达、鉴权失败、schema 违规三类错误有独立的错误码与可读消息
- [ ] 该 API 层有单元测试覆盖 CRUD 全路径与增量游标边界
