# E102：标准 MCP OAuth 接入

## 目标

工作区管理员登记 MCP 服务；成员在工作台应用页分别授权，平台只用该成员的令牌调用上游。OpenTask 与 GitLab MCP 通过标准元数据、OAuth 授权码与 PKCE S256 对接，不要求复制安装码或采用 E101 自定义安装协议。原授权码客户端和 E101 功能保持兼容。

## 方案

参考 MCP 2025-11-25 Authorization、RFC 9728、RFC 8414、RFC 7591、RFC 7636、RFC 8707。客户端先发现资源元数据和授权服务器元数据，校验 issuer 与端点，本次实现 RFC 7591 DCR；预登记公共客户端和 CIMD 尚未实现，不能宣称支持；服务发现、注册和成员授权属于不同步骤。管理员登记的 MCP 完整 URL 不得被假设为 `/mcp`。成员同意页只授予本人，授权 state、PKCE verifier 与工作区、成员和应用绑定；授权码兑换与后续 MCP 请求保持资源标识一致。令牌与客户端凭据只由服务端保管并按现有机制加密。

OpenTask 资源元数据公开授权服务器位置、授权服务器元数据公开实际能力。对标准客户端提供 DCR、S256 校验及资源绑定；DCR 支持公共客户端（none）和保密客户端（client_secret_post），已有 confidential client 保持兼容。公共客户端强制 PKCE，无客户端密钥。授权码必须在验证客户端、回调、PKCE 和资源后原子消费；并发重放不得成功。DCR 总量、频率和 scope 上界由服务端约束，不能因自动注册绕过用户同意或管理员策略。不同实现路径须按实际元数据判定，不用预注册凭据冒充支持 DCR 或 CIMD。

## 安全与兼容

标准模式要求 HTTPS；本地回环允许 HTTP。存量非回环 HTTP（包括公网地址）必须由管理员显式配置为兼容模式，界面提示明文传输并绑定管理员配置的目标；不把它标记成标准安全连接，也不默默降级 HTTPS。所有对外请求禁止跟随重定向、限定大小与时限；发现 URL 的 DNS、私网策略和信任边界与已授权的服务目标一致，禁止通过恶意元数据向其他目标发送凭据。标准 scope、userinfo 是否支持、资源 URI 与 token endpoint authentication method 由实际服务协商，GitLab 使用其文档要求的 MCP scope，不假定所有服务需要 userinfo。

## 验证

真实 OpenTask 后端与小蓝工作台完成管理员登记、成员授权、令牌兑换和 MCP 工具调用；多工作区/成员隔离、state 与 verifier 重放、错误资源、恶意元数据、拒绝授权、过期/刷新和 HTTP 兼容模式均需覆盖。对 GitLab 使用符合公开协议的 HTTP 交互桩并在可用真实实例时联调；未实际连接真实 GitLab 不宣称实测兼容。测试库与测试会话独立，不改生产。
