**Goal:** Workspace Triage intake queue (Linear-like): pending Issues list + accept into backlog / decline / mark duplicate; separate from personal Inbox notifications.

**Architecture:** Add nullable `issues.triage_status` (`pending`|`NULL`). `TriageService` lists/enqueues/accepts/declines/duplicates within `X-Workspace-Id`. Top-level `/api/triage` router (favorites/inbox pattern). Duplicate creates `IssueRelation(duplicates)` then applies decline semantics. FE: `/triage` page + sider link near Favorites; ⌘K nav action. Viewer GET-only; member/owner write.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, pytest+httpx, Vue3 + Naive UI, elegant-router, vitest optional.

**Service methods:**

```python
class TriageService:
    def __init__(self, db: AsyncSession): ...
    async def list_pending(self, workspace_id: str, *, page: int = 1, page_size: int = 50) -> tuple[list[dict], int]: ...
    async def enqueue(self, *, workspace_id: str, issue_id: str, actor_user_id: str) -> dict: ...
    async def create_and_enqueue(self, *, workspace_id: str, actor_user_id: str, title: str, type: str = "feedback", priority: str = "medium", description: str | None = None) -> dict: ...
    async def accept(self, *, workspace_id: str, issue_id: str) -> dict: ...
    async def decline(self, *, workspace_id: str, issue_id: str) -> dict: ...
    async def duplicate(self, *, workspace_id: str, issue_id: str, duplicate_of_issue_id: str, actor_user_id: str) -> dict: ...
```

Rules:
- `_get_pending_or_404` filters `Issue.workspace_id == workspace_id`
- `enqueue`: load issue in WS; if already pending return serialize; else set `pending`
- `create_and_enqueue`: use `IssueService.create_issue` (or minimal Issue insert with KEY-N via existing generator) then set pending — prefer `IssueService` to keep KEY-N
- `accept`: require pending; set `status="open"`, `triage_status=None`
- `decline`: require pending; set `status="rejected"`, `triage_status=None`
- `duplicate`: require both issues in same WS; create `IssueRelation(source_id=issue_id, target_id=duplicate_of, relation_type="duplicates")` via `IssueService.add_relation` if exists, else direct insert; then decline semantics on source
- `serialize_triage_issue(issue) -> dict` camelCase keys
