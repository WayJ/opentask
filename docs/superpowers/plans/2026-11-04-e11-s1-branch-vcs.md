# E11-S1 Branch naming + issue_vcs_links Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Linear-like `{issue_code}-{slug}` branch suggest/parse, `issue_vcs_links` on Issue (not Requirement/PGE), Issue FE「复制分支名」, and CLI commands on the **same HTTP API**.

**Architecture:** Pure helpers for slug/suggest/parse; Alembic `issue_vcs_links`; nested routes under `/api/issues/{issue_id}/vcs/*`; FE button calls GET branch-name + clipboard; CLI thin HTTP wrapper. No webhook (S2), no status hooks (S3), no live GitHub App.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, pytest/httpx, Vue3+Naive, click CLI.

## Global Constraints

- Branch template locked: `{issue_code}-{slug}` (KEY-N / legacy issue_code verbatim)
- New table `issue_vcs_links` — **never** `requirement_repos`
- CLI/Agent = same HTTP; camelCase responses
- No push; no S2 webhook; no S3 hook toggle product (columns may exist only if needed — prefer defer to S3)
- Alembic `down_revision = c3d4e5f6a7b8`; revision id `d4e5f6a7b8c9`
- ACL: `X-Workspace-Id` + require_workspace_context; viewer read; member+ write links
