# E11-S2 PR links + GitHub webhook Implementation Plan

> **For agentic workers:** Inline execution (no questions). Checkbox steps for tracking.

**Goal:** Complete PR association on `issue_vcs_links`, mockable GitHub PR webhook ingest, Issue detail PR panel, CLI `link-pr` on same HTTP. No status hooks (S3). No live GitHub App.

**Architecture:** Extend IssueVcsService with PATCH + `upsert_from_github_pr`; new router `POST /api/webhooks/github/pull-request` (optional HMAC); FE panel lists `kind=pull_request`; CLI posts camelCase body.

**Tech Stack:** FastAPI, SQLAlchemy, pytest/httpx, Vue3+Naive, click CLI.

## Global Constraints

- Table remains `issue_vcs_links` — never `requirement_repos`
- Webhook fixture-friendly; `WEBHOOK_GITHUB_SECRET` empty ⇒ skip signature verify (local/dev only)
- Match: (1) parse `head.ref` → issue_code → Issue (2) else existing link by `pr_url`/`external_id`
- Status: `merged` if merged; else map GitHub `state` (+ draft → `draft`)
- No S3 hooks; no push; Alembic tip stays `d4e5f6a7b8c9` unless schema gap (none expected)
